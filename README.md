# کاسپین نامبر — دفترچه تلفن سازمانی

وب‌اپلیکیشن (PWA) دفترچه تلفن هوشمند کارکنان:

- 🔐 **ورود اجباری** — دفترچه بدون حساب باز نمی‌شود؛ هر کارمند یوزر و رمز خودش را دارد
- 🔍 **جستجوی فارسی باگذشت** — «رضائی/رضایی»، بدون فاصله، با کلیدواژه‌ی شغلی («کی مسئول استخدامه؟»)
- 📞 **تماس با یک لمس** — `tel:` ، ذخیره مخاطبین (vCard)
- 📌 **سنجاق** — همکارهای پرتکرار بالای فهرست می‌نشینند (روی همان مرورگر ذخیره می‌شود)
- 📥 **ایمپورت اکسل/CSV** + فرم تکی
- 🙈 نصب روی گوشی (Add to Home Screen)
- 🧾 لاگ تغییرات و مدیریت کاربران در پنل ادمین

## ساختار

```
CaspianNumber/
├── backend/          # FastAPI + SQLAlchemy (SQLite / قابل تعویض با Postgres)
│   ├── app/
│   │   ├── core/persian.py    # نرمال‌سازی فارسی (ی/ي، ک/ك، اعداد، نیم‌فاصله…)
│   │   ├── models.py          # Employee / User / ChangeLog
│   │   ├── search.py          # موتور جستجو (stopword + scoring)
│   │   ├── importer.py        # ایمپورت اکسل/CSV با مپ هدر فارسی
│   │   └── routers/           # auth · employees · admin
├── frontend/         # React + Vite + TS + Tailwind (PWA, RTL, فونت وزیرمتن لوکال)
├── Dockerfile        # بیلد دو مرحله‌ای → یک کانتینر واحد
└── docker-compose.yml
```

## اجرا

### راه سریع (روی همین مک)

```bash
cd ~/dev/CaspianNumber
./run.sh          # اولین بار: خودکار venv می‌سازه و فرانت رو بیلد می‌کنه
```

بعد باز کن: **http://127.0.0.1:8899** — لاگین: `admin` / `admin123`

برای توسعه با هات‌ریلود:

```bash
./dev.sh          # بک‌اند روی 8899 + Vite روی 5173
```

> نیازمندی‌ها: `uv` و `node` — هر دو نصب‌اند. Docker لازم نیست.

### اجرا با Docker (روی VM شرکت)

```bash
# ۱) فایل .env بسازید:
cat > .env <<'EOF'
SECRET_KEY=<یک رشته تصادفی بلند>
ADMIN_USERNAME=admin
ADMIN_PASSWORD=<رمز قوی>
EOF

# ۲) بالا بیاورید:
docker compose up -d --build

# برنامه: http://<IP-VM>:8899
```

> ⚠️ اگر `docker pull` روی سرور کند/قطع است، میرور داخلی (آروان/های‌وب) را تنظیم کنید.

### دیپلوی عمومی روی `phone.rasha-paper.com`

در حالت production، کانتینر فقط روی `127.0.0.1:8899` در دسترس است و ترافیک
عمومی باید از Nginx روی پورت‌های ۸۰ و ۴۴۳ عبور کند. کانفیگ آماده در
`deploy/nginx/phone.rasha-paper.com.conf` قرار دارد.

قبل از اجرا، `.env.example` را به `.env` کپی کنید و دست‌کم `SECRET_KEY` و
`ADMIN_PASSWORD` را با مقادیر قوی جایگزین کنید. سپس:

```bash
docker compose up -d --build
curl -I http://127.0.0.1:8899
```

در DNS یک رکورد `A` برای `phone.rasha-paper.com` به IP عمومی سرور بسازید و
پورت‌های TCP 80/443 را تا این VM هدایت کنید. بعد از فعال‌کردن Nginx، گواهی
HTTPS را با Certbot صادر کنید.

## اجرای محلی (توسعه)

```bash
# بک‌اند
cd backend
uv run --with-requirements requirements.txt uvicorn app.main:app --port 8899

# فرانت (ترمینال دوم) — پروکسی /api روی 8899 تنظیم شده
cd frontend
npm install
npm run dev     # http://localhost:5173
```

## چه کسی به چه چیزی دسترسی دارد

**بدون حساب هیچ‌چیز دیده نمی‌شود.** هر مسیری جز `/login` — و هر مسیرِ `/api`
جز خودِ ورود — توکنِ معتبر می‌خواهد. کسی که آدرس را باز کند، اول صفحه‌ی ورود
را می‌بیند.

هر حساب به دقیقاً یک `organization_id` تعلق دارد و تمام جستجوها، CRUD،
ایمپورت و Audit در سرور با همان محدوده تقاطع داده می‌شوند. دفتر مرکزی یک
tenant مستقل است و به کارخانه‌ها دسترسی ضمنی ندارد.

| نقش | محدوده |
|---|---|
| `UNIT_USER` | مشاهدهٔ دفترچهٔ واحد خودش |
| `UNIT_MANAGER` | مدیریت کاربران و دادهٔ واحد خودش؛ حذف فقط با `can_delete_data` |
| `HEAD_OFFICE_ACCESS_ADMIN` | مدیریت واحد دفتر مرکزی و، فقط با `manage_global_admins`، اعطا/لغو مدیر کل |
| `GLOBAL_ADMIN` | مشاهدهٔ همه یا انتخاب یک واحد؛ MFA اجباری |

نقش مدیر کل فقط برای حسابی در دفتر مرکزی و فقط توسط کاربر دفتر مرکزی که
`manage_global_admins` دارد ایجاد یا لغو می‌شود. تغییر نقش خودِ کاربر و تعیین
`organization_id` از بدنهٔ رکوردهای داده رد می‌شود.

## ورود اولیه

- کاربر پیش‌فرض: `ADMIN_USERNAME` / مقدار `ADMIN_PASSWORD`. این حساب نقش
  `HEAD_OFFICE_ACCESS_ADMIN` و مجوز `manage_global_admins` دارد، اما مدیر کل
  نیست و دادهٔ کارخانه‌ها را نمی‌بیند.
- مسیر پنل: `/admin`
- اولین کار: تب «پرسنل» → **⬆️ ایمپورت اکسل/CSV**
  - ایمپورت فقط دفترچه را پر می‌کند و حسابی نمی‌سازد
  - ستون‌ها بر اساس هدر فارسی تشخیص داده می‌شوند (نام، شماره داخلی، شماره مستقیم، …)
- تب «کاربران»: برای هر کارمند یک حساب بسازید (بدونِ آن دفترچه را نمی‌بیند).
  رمز دیده نمی‌شود — سرور رمزِ موقت می‌سازد و فقط همان لحظه نشان می‌دهد؛
  همان را به صاحبش بدهید. رمزِ موقت با `tmp-` شروع می‌شود و کاربر سرِ اولین
  ورود باید رمز خودش را بگذارد. نقش و مجوز حذف نیز در همان فرم تعیین می‌شود.
- پس از ساخت اولین `GLOBAL_ADMIN`، ورود نخست او راه‌اندازی Authenticator را
  اجباری می‌کند و کدهای بازیابی فقط یک‌بار نمایش داده می‌شوند.

## Migration

در کانتینر، `alembic upgrade head` پیش از اجرای سرویس انجام می‌شود. اجرای دستی:

```bash
cd backend
python -m alembic upgrade head
```

## شماره‌ی مستقیم

شماره‌ی موبایلِ شخصی از دفترچه حذف شده. به‌جای آن هر نفر یک **شماره‌ی مستقیم**
دارد که کاربر از گوشی‌اش می‌گیرد و مستقیم به همان داخلی می‌رسد:

```
پیش‌شماره + داخلی      →  02144 + 218 = 02144218
```

پیش‌شماره با `DIRECT_PREFIX` در `.env` تنظیم می‌شود (پیش‌فرض `02144`). شماره
خودکار از روی داخلی ساخته می‌شود؛ اگر کسی خطِ مستقیمِ متفاوتی دارد، در پنل
مدیریت فیلد «شماره مستقیم» را دستی پر کنید و همان می‌ماند.

## تکمیل با هوش مصنوعی

در فرمِ افزودن/ویرایش پرسنل، چهار فیلدِ «کلیدواژه‌ها»، «مهارت‌ها»، «زبان‌ها» و
«یادداشت» از بقیه‌ی فرم جدا شده‌اند و یک دکمه دارند که از روی نام، سمت، واحد،
شرکت و محل خدمت پرشان می‌کند. پیشنهاد است، نه ذخیره: در فرم می‌نشیند تا قبل از
زدنِ «ذخیره» درستش کنید.

سرویس باید سازگار با OpenAI باشد. در `.env`:

```
AI_BASE_URL=https://api.openai.com/v1
AI_API_KEY=<کلید>
AI_MODEL=gpt-4o-mini
```

بدونِ `AI_API_KEY` دکمه خطای روشن می‌دهد و بقیه‌ی برنامه مثل قبل کار می‌کند.
شماره‌ها و ایمیل به سرویس فرستاده نمی‌شوند — فقط نام و مشخصاتِ شغلی.

## نکته‌ی امنیتی

- حتماً `SECRET_KEY` و رمز ادمین را عوض کنید. `SECRET_KEY` توکن‌ها را امضا
  می‌کند؛ با مقدارِ پیش‌فرض هرکسی می‌تواند برای خودش توکنِ معتبر بسازد و از
  ورود رد شود. عوض کردنِ آن همه را یک‌بار بیرون می‌اندازد (دوباره وارد شوند).
- رمزها **فقط به‌صورت هشِ bcrypt-sha256** ذخیره می‌شوند (هش‌های bcrypt قدیمی
  نیز هنگام مهاجرت قابل اعتبارسنجی می‌مانند)؛ هیچ‌کس — ادمینِ دیگر هم —
  رمزِ کسی را از سیستم نمی‌خواند. اگر کسی رمزش را گم کرد، در تب «کاربران» دکمه‌ی
  **رمز موقت** رمزِ یک‌بارمصرفی می‌سازد که همان لحظه نشان داده می‌شود و بعد از
  بستنِ کارت از هیچ‌جا قابل بازیابی نیست. رمزِ موقت با `tmp-` شروع می‌شود و
  صاحبش سرِ اولین ورود باید رمز خودش را بگذارد.
- **گارد سمت سرور است، نه فقط در frontend** — lookup مستقیم شناسه، query
  `organization_id`، bulk payload و import همگی tenant-scoped هستند. درخواست
  خارج از محدوده `404` می‌گیرد تا وجود رکورد tenant دیگر نیز افشا نشود.
- ورود موفق/ناموفق، مشاهدهٔ دفترچه و دادهٔ حساس، CRUD، import، تغییر رمز،
  تغییر وضعیت و نقش همراه actor، نقش قبل/بعد، زمان، IP و user-agent در Audit
  ثبت می‌شوند.
- سنجاق‌ها در `localStorage` همان مرورگر می‌مانند (به‌نامِ کاربرِ وارد شده) و
  هیچ‌وقت به سرور نمی‌روند؛ روی دستگاهِ دیگر دیده نمی‌شوند.
- HTTPS را روی reverse-proxy داخلی (nginx) فعال کنید؛ دکمه‌ی تماس (`tel:`) و نصب PWA روی HTTP محدود است.
- بک‌آپ روزانه: `docker exec caspian-number cp /data/caspian.db /data/backups/$(date +%F).db`
